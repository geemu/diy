# v0.48.0 变更说明

## 目标

把 v0.47 的“搭型材 + 自动连接 + 快速换连接”继续推进到 IdeaBuilder 式新手配置器：用户不需要手动计算板材净尺寸或逐根搭门框。

## 1. Frame Opening Resolver

新增 `static/js/configurator/FrameOpeningResolver.js`。

首版明确只接受：

- 4 根直线型材；
- 两组互相垂直的平行边；
- 处于同一世界平面；
- 轴对齐矩形框口。

输出净开口宽高、中心、世界方向和宿主 Part IDs。斜框、任意四边形和曲线框口不在 v0.48 自动猜测范围内。

## 2. Panel Configurator

`PanelDoorConfigurator.createPanelFromSelection()` 将框口描述转换为普通 `PANEL`：

- 四边间隙；
- 板厚；
- 材质；
- 法向偏移；
- 自动继承单一宿主 Assembly（如果四边属于同一组件）。

自动板写入 `panelSpec.configurator=FRAME_OPENING_PANEL` 和 `sourcePartIds`。`refitPanel()` 可在宿主尺寸变化后重新计算板材宽高和位置。

## 3. Door Configurator

门不是新 PartType，而是：

```text
Assembly
├─ PROFILE × 4
├─ PANEL × 1
├─ HINGE × 2（可选）
└─ HANDLE × 1（可选）
```

门框四根型材仍进入 `AutoConnectionResolver -> ConnectionManager`，因此五金、加工和 BOM 保持单一事实源。

Assembly 写入：

- `kind=DOOR`；
- `configurator=DOOR_CONFIGURATOR`；
- `parameters.sourcePartIds`；
- 门框型号、留缝、门芯参数、铰链方向等。

生成成员写入 `configuratorId/configuratorRole`。`refitDoor()` 会按当前宿主框口重新生成门组件，同时保持 Assembly ID。

## 4. Profile Replacement

新增 `ProfileReplacementManager`。

范围：

- 当前选择；
- 当前组件全部型材；
- 工程内与当前构件同型号的全部型材。

保证：

- Part ID 不变；
- 中心线不变；
- 长度不变；
- position / rotation 不变；
- Assembly 不变。

替换截面后统一重建 Mesh 和相关连接。若原连接因新槽宽/系列不兼容，可调用现有 Quick Change 推荐规则自动修复；找不到兼容规则则保留 INVALID，不静默删除。

## 5. 通用门五金

新增不绑定厂商的参数化内置五金：

- `HINGE_GENERIC_40`；
- `HANDLE_GENERIC_120`。

它们进入既有 Hardware BOM；后续可由数据库标准配件目录替换为用户实际采购型号。

## 6. 数据模型

- Project Schema：41（不变）
- `panelDoorConfiguratorVersion=1`
- `profileReplacementVersion=1`
