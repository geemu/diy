# v0.45.0 变更说明

## 1. SQLite 成为唯一数据库基线

v0.45.0 将运行时目录数据库从 MySQL 切换为 SQLite，目标是适配“每个玩家在自己的 Windows 电脑本地运行”的产品形态。

当前链路：

```text
Controller -> Service -> Mapper -> Mapper.xml -> SQLite
```

关键变化：

- `pom.xml` 移除 `mysql-connector-j`，改用 `org.xerial:sqlite-jdbc:3.53.4.0`。
- 默认数据库文件：`./data/aluminum-cad.db`。
- `schema.sql` 使用 SQLite 类型、索引和自增语法。
- `data.sql` 使用 `ON CONFLICT ... DO UPDATE` 做幂等初始化。
- Profile Catalog 的 Upsert 同步切换为 SQLite `ON CONFLICT(id)`。
- JSON 继续作为业务字符串通过现有 TypeHandler 读写，不依赖 MySQL JSON 列类型。
- MyBatis XML、BaseMapper 公共片段和 Java 分层规则保持不变。

Project JSON 仍然是工程事实来源；SQLite 负责本地目录主数据，不把 Three.js Scene 当持久化模型。

## 2. DIY 快速设计 1.0

新增：

```text
static/js/diy/
├── DiyTemplateCatalog.js
└── DiyGenerator.js
```

第一批模板：

- 基础空间框；
- 多层置物架；
- 鱼缸 / 龟缸架；
- 设备机架。

用户只需选择用途、型材和宽/深/高；多层架再填写层数与每层中间承托梁数量。

模板不会直接创建 Three.js Mesh，而是调用现有 Editor 领域 API。新增 `Editor.addLayeredRack()` 统一生成多层型材架，保证 Undo、Project JSON、BOM、工程图仍消费同一套 Part 模型。

当前模板阶段只负责“快速生成结构本体”。自动连接件/紧固件、结构建议和更丰富的参数联动继续放到后续版本，不在模板层重复实现 Connection/Machining 逻辑。

## 3. 产品方向

v0.45 开始明确区分：

```text
DIY 快速设计（默认新手入口）
        ↓
标准 Project / Editor 模型
        ↓
专业 CAD 细调
        ↓
连接 / 加工 / BOM / 工程图 / 制造包
```

参考 80/20 IdeaBuilder 的“快速配置 + 拖拽吸附 + 自动制造输出”交互思路，但保留 ALU CAD 自己的 Project Schema、连接、加工、工程图和导出链。

- Project Schema：仍为 `41`
